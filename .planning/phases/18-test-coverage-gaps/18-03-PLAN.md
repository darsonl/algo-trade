<objective>
Add quota-exhaustion tests (TEST-11, D-03) for BOTH scan paths: when all three configured providers
(primary + fallback + fallback2) are at/over analyst_daily_limit, the buy path must not call
analyze_ticker and the sell path must not call analyze_sell_ticker.

Purpose: The D-11 quota guard at main.py:198-201 (buy) and main.py:343-346 (sell) is the only thing
preventing the bot from blowing past Gemini free-tier daily limits. It is currently untested.
Output: One test in tests/test_main.py (buy) and one in tests/test_sell_scan.py (sell). No production changes.

CRITICAL — false-green guards (from advisor + 18-CONTEXT D-03):
  - The config MUST configure all THREE provider slots with NON-EMPTY provider names. The guard
    short-circuits any UNSET fallback provider to `analyst_daily_limit` (main.py:189/196) — so a config
    missing fallback2 would trip the guard "for free" and pass while fallback2 is still under quota. That
    is the exact "exhausting only two is a false green" the spec warns about. Three real providers + a mock
    returning >= limit for ALL of them is the only valid setup.
  - assert_not_called() is meaningless unless the harness would OTHERWISE reach the analyze call. Model the
    buy test on test_run_scan_cache_miss_calls_analyze_ticker (which proves the harness reaches
    analyze_ticker) and the sell test on test_sell_pass_posts_sell_recommendation (which proves it reaches
    analyze_sell_ticker). Start from those exact mock stacks, then flip get_analyst_call_count_today to
    return >= limit and assert_not_called.
</objective>
