<!-- From config.py — validate() checks these fields in order and raises ValueError for the first empty one. -->
<!-- Required fields (each its own raise): schwab_app_key, schwab_app_secret, discord_token, -->
<!-- then the ANALYST_PROVIDER branch, then discord_channel_id, then schwab_account_hash. -->

def validate(self):
    if not self.schwab_app_key:            raise ValueError("SCHWAB_APP_KEY is required in .env")
    if not self.schwab_app_secret:         raise ValueError("SCHWAB_APP_SECRET is required in .env")
    if not self.discord_token:             raise ValueError("DISCORD_TOKEN is required in .env")
    if self.analyst_provider == "claude":
        if not (self.analyst_api_key or self.anthropic_api_key):
            raise ValueError("ANTHROPIC_API_KEY (or ANALYST_API_KEY) is required when ANALYST_PROVIDER=claude")
    else:
        if not self.analyst_api_key:
            raise ValueError(f"ANALYST_API_KEY is required when ANALYST_PROVIDER={self.analyst_provider}")
    if not self.discord_channel_id:        raise ValueError("DISCORD_CHANNEL_ID is required in .env")
    if not self.schwab_account_hash:       raise ValueError("SCHWAB_ACCOUNT_HASH is required in .env")

# discord_channel_id is an int (0 is falsy → triggers raise). All others are strings.

<gotchas>
- validate() checks fields IN ORDER and raises on the FIRST empty one. To test "missing field X raises",
  every OTHER required field must be populated, otherwise an earlier check fires and the test passes for
  the wrong reason. Use a _valid_config() helper and blank exactly one field per test.
- For the claude branch happy-path/missing tests: set analyst_provider="claude" and control
  analyst_api_key / anthropic_api_key explicitly. For the other-provider branch: set
  analyst_provider="gemini" (or any non-claude) and control analyst_api_key.
- USE_LIMIT_BUY reload: load_dotenv() runs at config import and can repopulate USE_LIMIT_BUY from a real
  .env on the dev machine, polluting the "unset" case. The unset test MUST neutralize this — use
  monkeypatch.delenv("USE_LIMIT_BUY", raising=False) AND guard against .env by also patching
  load_dotenv to a no-op during the reload, OR monkeypatch.setenv to the explicit case and only treat
  delenv as the "unset" case after confirming no .env override. Simplest robust approach: in each mapping
  test, monkeypatch.setattr("config.load_dotenv", lambda *a, **k: None) is NOT possible post-import for
  the default; instead patch os.getenv is fragile — prefer: monkeypatch.setenv / delenv then
  importlib.reload(config) and read config.Config().use_limit_buy. If a stray .env sets USE_LIMIT_BUY,
  the unset test must still see False — so the test should ALSO monkeypatch.setenv("USE_LIMIT_BUY","")
  is wrong (empty != unset). Use delenv and, to be safe against .env, the executor may patch
  config.load_dotenv before reload via monkeypatch on the module attribute and reload twice. Document the
  chosen mechanism in a comment.
</gotchas>

    The mapping is frozen in the field default at import, so tests MUST reload the config module after
    setting the env var. Use pytest's `monkeypatch` fixture. To prevent a real on-disk .env from
    repopulating USE_LIMIT_BUY during reload (which would corrupt the unset case), neutralize load_dotenv

      def _reload_with_env(monkeypatch, value):
          import config as config_module
          import importlib
          # Neutralize .env so only the explicit env var (or its absence) drives the mapping
          monkeypatch.setattr(config_module, "load_dotenv", lambda *a, **k: None)
          if value is None:
              monkeypatch.delenv("USE_LIMIT_BUY", raising=False)
          else:
              monkeypatch.setenv("USE_LIMIT_BUY", value)
          importlib.reload(config_module)
          return config_module.Config().use_limit_buy

    NOTE: after reload, config_module.load_dotenv is reset to the real function (reload re-imports the
