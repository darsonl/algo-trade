<!-- then the ANALYST_PROVIDER branch, then discord_channel_id, then schwab_account_hash. -->

def validate(self):
    if not self.schwab_app_key:            raise ValueError("SCHWAB_APP_KEY is required in .env")
    if not self.schwab_app_secret:         raise ValueError("SCHWAB_APP_SECRET is required in .env")
    if not self.discord_token:             raise ValueError("DISCORD_TOKEN is required in .env")
    if self.analyst_provider == "claude":
        if not (self.analyst_api_key or self.anthropic_api_key):
            raise ValueError("ANTHROPIC_API_KEY (or ANALYST_API_KEY) is required when ANALYST_PROVIDER=claude")
    else:
        if not self.analyst_api_key:
            raise ValueError(f"ANALYST_API_KEY is required when ANALYST_PROVIDER={self.analyst_provider}")
    if not self.discord_channel_id:        raise ValueError("DISCORD_CHANNEL_ID is required in .env")
    if not self.schwab_account_hash:       raise ValueError("SCHWAB_ACCOUNT_HASH is required in .env")

# discord_channel_id is an int (0 is falsy → triggers raise). All others are strings.
# USE_LIMIT_BUY mapping: use_limit_buy: bool = os.getenv("USE_LIMIT_BUY", "false").lower() == "true"
#   (config.py line 38). This is evaluated at MODULE IMPORT, so changing the env requires importlib.reload(config).
# config.py line 4 is `from dotenv import load_dotenv`; line 6 calls load_dotenv(...). importlib.reload
#   RE-EXECUTES the whole module body, so line 4 rebinds config.load_dotenv to the real dotenv function on
#   every reload — see the gotcha below for why the noop must be patched on the SOURCE (dotenv.load_dotenv).

<gotchas>
- validate() checks fields IN ORDER and raises on the FIRST empty one. To test "missing field X raises",
  every OTHER required field must be populated, otherwise an earlier check fires and the test passes for
  the wrong reason. Use a _valid_config() helper and blank exactly one field per test.
- For the claude branch happy-path/missing tests: set analyst_provider="claude" and control
  analyst_api_key / anthropic_api_key explicitly. For the other-provider branch: set
  analyst_provider="gemini" (or any non-claude) and control analyst_api_key.
- USE_LIMIT_BUY reload: load_dotenv() runs at config import (line 6) and can repopulate USE_LIMIT_BUY from
  a real .env on the dev machine, polluting the "unset" case. You CANNOT neutralize this by patching
  `config.load_dotenv` and then reloading: importlib.reload re-executes config.py's line 4
  `from dotenv import load_dotenv`, which REBINDS config.load_dotenv back to the real function BEFORE line 6
  runs — so the noop is destroyed before it ever fires. The fix is to patch the SOURCE module
  `dotenv.load_dotenv`. When reload re-runs `from dotenv import load_dotenv`, it looks up dotenv.load_dotenv
  at that instant; if that is already the noop, the noop is what gets bound into config's namespace, so
  line 6 is a no-op and the .env never repopulates USE_LIMIT_BUY. monkeypatch restores dotenv.load_dotenv
  automatically on teardown. Combine with monkeypatch.delenv("USE_LIMIT_BUY", raising=False) for the unset
  case and monkeypatch.setenv for the explicit cases.
</gotchas>

      def _reload_with_env(monkeypatch, value):
          import config as config_module
          import importlib
          import dotenv
          # Patch the SOURCE module — survives reload's `from dotenv import load_dotenv` rebind (config.py
          # line 4 re-runs on every reload and would otherwise restore the real load_dotenv before line 6).
          monkeypatch.setattr(dotenv, "load_dotenv", lambda *a, **k: None)
          if value is None:
              monkeypatch.delenv("USE_LIMIT_BUY", raising=False)
          else:
              monkeypatch.setenv("USE_LIMIT_BUY", value)
          importlib.reload(config_module)
          return config_module.Config().use_limit_buy

    Why the source patch (and not config.load_dotenv): importlib.reload re-executes config.py's body,
    including line 4 `from dotenv import load_dotenv`. That line looks up `dotenv.load_dotenv` at reload time
    and rebinds config's local name to it. If you patch `config.load_dotenv`, the rebind on line 4 destroys
    the noop BEFORE line 6's `load_dotenv(...)` call fires, so the real .env still loads. Patching
    `dotenv.load_dotenv` means the name line 4 imports IS already the noop, so line 6 is a no-op and the
    .env never repopulates USE_LIMIT_BUY. monkeypatch restores dotenv.load_dotenv automatically on teardown.
