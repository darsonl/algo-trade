## v1 Requirements

### Risk Management

- [x] **RISK-01**: User can approve a buy recommendation and have a limit order placed at the signal price (not a market order) — *Phase 17; code-complete + unit-tested, live UAT deferred*
- [x] **RISK-02**: `USE_LIMIT_BUY` config flag controls limit order behavior — operator can opt out via `.env` — *Phase 17; default flipped to `false` 2026-06-06 pending live verification*
- [x] **RISK-03**: `limit_price` and `order_type` stored in `trades` table for audit trail — *Phase 17; additive migration*
- [x] **RISK-04**: Approve embed shows scan-time price with timestamp ("as of HH:MM") so operator can assess staleness — *Phase 17*

### Signal Intelligence

- [x] **SIG-05**: BUY embed displays next earnings date field (sourced from `info["earningsTimestamp"]` — no extra HTTP call) — *Phase 16*
- [x] **SIG-06**: Next earnings date included in Claude BUY prompt so it can factor in proximity risk — *Phase 16*
- [x] **SIG-07**: P/E direction (expanding / contracting / stable / N/A) included in Claude BUY prompt using `forwardPE` vs `trailingPE` as proxy — *Phase 15*
- [x] **SIG-08**: Quarterly EPS trend (last 4 quarters from `ticker.quarterly_income_stmt`) included in Claude BUY prompt — *Phase 15*

### Operational Quality

- [x] **OPS-02**: `/history` Discord slash command shows last 20 closed trades — ticker, entry price, exit price, P&L%, sell date — *Phase 14*

### Test Coverage

- [x] **TEST-09**: Analyst fallback provider logic tested — primary API failure triggers fallback; parse errors ALSO trigger fallback (reversed 2026-06-06 — Gemini free model returns unparseable output; commit `1cb80f6`). Both failure types converge on the `primary → fallback → fallback2` chain. — *Phase 18-01*
- [x] **TEST-10**: Config `validate()` tested — missing required env vars raise `ValueError` (both `ANALYST_PROVIDER` branches); a fully-valid config passes; `USE_LIMIT_BUY` maps correctly (unset → `False` default, `=false` → `False`, `=true` → `True`) — *Phase 18-02*
- [x] **TEST-11**: `run_scan` quota exhaustion path tested — when ALL configured providers (primary + both fallbacks) hit the daily limit, neither `analyze_ticker` (buy) nor `analyze_sell_ticker` (sell) is called — *Phase 18-03*

- Historical P/E via price/EPS computation — `forwardPE` vs `trailingPE` proxy sufficient
