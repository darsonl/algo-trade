## What is implemented

All in `database/order_accounting.py`, `database/queries.py`, `database/models.py`,
`schwab_client/order_payload.py`.

- **`order_commitment(row)`** — daily-notional cost. Open orders price at the **limit**, not the
  quote. Terminal orders keep what filled. **Unobserved** fill data keeps the FULL commitment
  (`fills_observed` gates the release, because an unverified `0` is not evidence of no fill).
- **`remaining_buy_reservation(row)`** — portfolio cost, **deliberately a different number**:
  broker position market value already counts filled shares, so reusing commitment would charge
  them twice.
- **`orders` table** + CRUD taking a **connection, not a db_path** — the cap check and the
  reservation that consumes it must be one transaction. `immediate_transaction()` takes the
  write lock up front via `BEGIN IMMEDIATE` and rolls back on any exception.
- **`sweep_stale_pending_submits`** — the crash window. A row committed before submission whose
  process died is unreachable; this moves it to `submit_unknown` (resubmits nothing).
- **`resolve_order_manually`** — audited operator override. `adopt` / `confirmed_absent` /
  `keep_blocked`, append-only event log, actor and evidence mandatory.
- **`adopt_replacement`** — follows `replacingOrderCollection` to the successor and inserts it
  with **its own** quantity and limit. Anything ambiguous keeps the predecessor fully reserved.
- **`record_candidate_observation`** — durable, **monotonic** worst-case reservation while a
  submission is ambiguous.
- **`kill_switch`** (`risk/kill_switch.py`) — durable, cross-process, fail-closed. State is in
  SQLite so a `/halt` in one process stops the others and survives restart; `is_enabled()`
  re-reads on every call for exactly that reason. `submission_gate()` is an `asyncio.Lock`
  **per running loop**. Checked both at the sink (`_call_place_order`) and in the approval
  path inside the gate. `/halt` persists first, then awaits the gate.
- **`quotes`** (`schwab_client/quotes.py`) — validated bid/ask with **no defaults**: every field
  mandatory, every failure raises, transport checked before parsing. Freshness enforced
  separately (`QUOTE_MAX_AGE_S`), `age_seconds` clamped at zero against clock skew.
  `marketable_sell_limit` prices `bid * (1 - buffer/100)` rounded **down** to the tick. Sells are
  DAY marketable limits; buys stay passive GTC. **No market-order fallback** — no usable quote
  means no sell, and the recommendation re-opens.
- **`ops_alerts` outbox** (`discord_bot/bot.py`) — `send_ops_alert` persists the alert **before**
  attempting delivery, so a Discord outage leaves a durable row instead of a log line. A failed
  send increments `attempts` and keeps `delivered_at` NULL; `drain_ops_alerts` retries the
  backlog oldest-first at the start of every scan and **stops at the first still-failing alert**,
  since an outage is not a per-alert condition. Neither the send nor the drain ever raises — both
  run inside scans that must not be aborted by their own reporting.

## ⚠️ START HERE — what remains

### Decided, not yet implemented

**Round-5 #7 — after-hours session attribution.** An order entered Friday night buckets to
Friday by `submitted_at`, but Schwab queues it for **Monday's** regular session. Monday's
ceiling then resets and admits another full allowance, and both can fill Monday against one
ceiling. `market_session_date()` returns an Eastern *calendar* date; `market_time.py`
deliberately has no exchange calendar.

**Decision (2026-08-15): add a real trading calendar** plus an `intended_session_date` column,
and bucket the ceiling by intended session rather than by `submitted_at`. Blocking
after-hours/weekend submissions was considered and **rejected**. Not yet implemented — the daily
ceiling keeps its known hole until this lands, which is tolerable only while `DRY_RUN=true`.
Expect a new dependency (`exchange-calendars` or similar) that `market_time.py` avoided on
purpose, the `ALTER TABLE` idiom for the new column, and an entry in `tests/test_db_migrations.py`.

#### What #4 turned up

The reviewer asked whether `/halt` could deadlock the loop. Running it gave a worse
answer: `threading.RLock` is reentrant **per thread**, and every coroutine shares the
loop thread, so `/halt` acquiring the "same gate" as an in-flight submission succeeded
immediately — observed order `["submit-enter", "halt-acquired", "submit-exit"]`. Spec
v4's gate provided **no mutual exclusion at all** in the ordinary case. A deadlock would
at least have been loud.

Replacing it with a module-level `asyncio.Lock` then introduced a second, subtler bug: a
lock binds to the first loop that **contends** on it and raises for every loop after, and
`acquire()`'s uncontended fast path never touches the loop — so the first test written
passed and proved nothing. Forcing contention failed instantly. The gate is now one lock
per running loop in a `WeakKeyDictionary`. Both behaviours are pinned by
`tests/test_kill_switch_gate.py`; do not "simplify" them back.

**Deviation from spec v4, flagged deliberately:** `TRADING_ENABLED` defaults to **false**,
not true. A new deployment is armed by an explicit `/resume` rather than by a config file
nobody re-read. Override in `.env` if you disagree — the seed applies only to a database
that has never been written.

After those, the approval path can be wired onto the ledger (spec v4 build steps 8–13).

| Round | Result |

Not converging. Round 4 found that two of v3's *fixes* were themselves defects. Round 5 found

places. Meanwhile the one defect actually *proven* rather than argued — `get_positions` raising

**The design docs are still useful as a requirements list.** `specs/2026-08-14-live-trading-safety-design.md`

unverified prose, not as truth. Review findings live in the round-4 and round-5 prompts under

## Four defect shapes that keep recurring

1. **A prose claim naming no implementation.** "The sink re-reads it", "reconciliation resolves
   it", "`/resolve` accepts a manual override" — each read as settled, none existed.
2. **Defensive parsing of an unvalidated response** turns an error into confident data.
   `get_positions` had no `raise_for_status`, so a 401 body became `[]` = "account holds
   nothing", and a broker outage *opened* the size guards.
3. **Reachability, not just correctness.** Code can be correct and never reached. Three review
   rounds read `get_positions` and missed that it crashed on every call — CI was green because
   no test called it, and `main.py` swallowed the exception.
4. **Absence of data is not data.** Appeared three times: the fail-open parse, the unverified
   zero fill (`fills_observed`), and disappearing `/resolve` candidates (monotonic reservation).

Also: `CREATE TABLE IF NOT EXISTS` does nothing on an existing table, so every new column needs
the `ALTER TABLE` idiom. `tests/test_db_migrations.py` builds the legacy schema explicitly —
add to it whenever a column is added.

## Conventions worth not rediscovering

- **Day bucketing** = US market session via `market_time.market_session_bounds_utc()` as a range
  predicate. Never `'localtime'`, never bare UTC. On this UTC+8 host the 21:45/03:30 scans are
  one session but two local dates.
- **Order CRUD takes `conn`**, unlike the rest of `queries.py`, on purpose (see above).
- **Tests reaching Schwab must pin `dry_run=True`** regardless of `.env`.
- **Terminal statuses are an allowlist**, never a denylist — Schwab's enum has a literal
  `UNKNOWN` member.
- schwab-py is **1.5.1**, locked and installed. `schwab.Client` does NOT exist; it is
  `schwab.client.Client`.
