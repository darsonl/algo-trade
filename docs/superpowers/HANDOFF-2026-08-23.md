### Forward marks had TWO defects, and the undocumented one was worse

`reference_price` is a raw live quote frozen at the screen. Every close Yahoo serves is on the
basis as of **fetch time**. The two ends of the stock's return sat on different bases.

**Splits** — documented as a known hazard for months, but the docstring named the wrong
mechanism (it blamed back-adjustment of the *exit*; marks are taken shortly after maturity, so
almost nothing is back-adjusted into the exit). Also verified, and it kills the obvious fix:

> **`auto_adjust` does NOT control split adjustment.** NVDA's real 2024-06-05 close was ~$1224;
> both `auto_adjust=True` and `False` report ~$122. The flag toggles only the *dividend* leg.

Live measurement: a holding that gained **+5.86%** would have recorded as **−89.41%**.

**Dividends** — not previously identified, and larger in aggregate because it touched *every*
row. The benchmark's entry is a past date fetched now, so it absorbs every SPY distribution
since (**total** return); `reference_price` absorbs nothing (**price** return). Since only the
stock side was affected, the whole gap fell through into excess return:

| | old | new | excess understated by |
|---|---|---|---|
| KO | 13.35% | 14.87% | 1.52pp |
| XOM | 12.81% | 14.31% | 1.50pp |
| T | −10.11% | −7.96% | 2.16pp |

The screen selects **on dividend yield**, so the bias was correlated with the variable under
test and would not have averaged out.

**The fix.** Both factors are reconstructed over `(session_date, as_of]` from the `Dividends`
and `Stock Splits` columns rather than inherited from fetch-time adjustment, so a mark taken
late equals one taken promptly. The intraday decision price is kept — re-basing corrects for
corporate actions only.

### Details that will look like details and are not

- **The seam had to move.** A corporate action is a property of the *span between* two dates.
  The old `(ticker, as_of) → float` stub could not express one at all, which is why
  `test_shadow_outcomes.py` changes. Hard to test meant the interface was wrong.
- **`record_shadow_outcome` takes the `Mark` objects whole**, not loose floats — a `return_pct`
  cannot then be stored beside factors that disagree with it, which is the exact defect class.
- **An unpriceable dividend yields `None`, never `1.0`**; the mark stays pending. A silent
  under-correction is the `fills_observed` failure in a new place.
- **The new columns stay NULL on pre-existing rows.** `1.0` would falsely claim a quiet window.
- **No backfill needed** — `shadow_outcomes` was empty. That is precisely why this had to land
  before 2026-08-27.

### ⚠️ A method failure worth carrying forward

The first mutation run reported **"6 passed"** for two boundary mutations that had **silently
never been applied** — Git Bash `/tmp` and Windows Python's `/tmp` are different directories,
so the mutation script tracebacked and the *unmutated* tests passed. It read as "the tests have
teeth" and meant the opposite.

**A mutation that reports a false PASS is worse than no mutation testing**, because it certifies
the inverse of the truth. Assert the anchor was found, and use the scratchpad path.

## 2b. Also this session

### The analyst chain was probed and left alone, on purpose (PR #39)

`gemini-3.7-flash` parses **12/18** across two sessions; `deepseek-v4-flash` parses **18/18**
and is a different *provider*. On parse rate alone the tiers should swap.

**Decided against by the owner: deepseek costs money.** A free model that parses two times in
three, in front of a paid one, is a **cost filter** — it absorbs ~67% of fallback traffic for
nothing. The wasted call and ~12s of latency on the other third is the price.

Recorded in CLAUDE.md because the document as written argued the opposite: "a model that cannot
parse contributes nothing but latency" is the Gemma precedent, and it assumes every tier costs
the same. **Do not apply it mechanically here.**

The failures are clean PARSE failures, not 503s — so this is not the quota-exhaustion misread
this same model already caused once.

### Gate provenance (PR #40)

`evaluate_fundamentals` / `evaluate_technicals` return a `Verdict` instead of a bool; every
observation now records `gate_config_json` and a specific `reject_reason`.

**The backlog item was broader than the real gap.** `fundamentals_json` already stores the whole
185-key `.info` dict — all three gate inputs present on 39/39 live rejected rows — so "would
this have passed threshold set X" was always recomputable. What is irrecoverable is the
**pipeline branch**: a fundamentally-rejected candidate never got an analyst call, so re-grading
it later still yields no signal. This buys correct cohort *labelling*, not re-running history.

### End-to-end proof of the marking path

`mark_due_outcomes` was run against **live yfinance on a copy of the real database** — 12 marks
in 3.5s. NVDA's split detected as 10.0 at all four horizons, dividend factors accumulating
correctly as horizons lengthen, and two tickers sharing a session date reporting identical
benchmark returns (so the benchmark really is computed once per session/horizon). Network cost:
**20 fetches vs 22** under the old design, so the "same request count" claim holds, measured.
