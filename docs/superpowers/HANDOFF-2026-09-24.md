## 2. What happened, and the reasoning not in the code

### 2a. The quota counter was measuring the wrong unit, and the SDK was the bigger half

`analyst_calls` recorded **50** attempts for the 09-23 session. The AI Studio dashboard recorded
**~205 requests**. Two retry layers multiplied under one counted attempt:

| layer | value | who set it |
|---|---|---|
| `@_retry` (tenacity) | `stop_after_attempt(3)` | us, deliberately |
| SDK `max_retries` | **2** | **nobody — it is the default** in *both* `openai` and `anthropic` |

One logical call was worth up to **9** requests. The counter's own docstring had called this "close
enough"; that judgement had never been measured and was off by 4×.

**`_should_retry` could never have bounded it**, for two independent reasons. It governs only the
tenacity layer — the SDK retries underneath it regardless — and it short-circuits solely on a
`QuotaFailure`/`PerDay` detail, which the **503 "high demand"** body this tier actually returns does
not carry. That is the fourth appearance of this project's signature trap: *a refusal that does not
look like a refusal is still a refusal* (the Gemini 503s, Alpha Vantage's HTTP 200 quota body, the
`finish_reason='length'` empty completion, now this).

**`gemini-3.7-flash` is what made the diagnosis attributable.** Flash-lite's usage was jointly
caused — see §2b — so no amount of staring at it separates amplification from contention. Nothing
else calls 3.7-flash, so its numbers isolate one mechanism: **23/20 RPD and 7/5 RPM against 7
counted**. Seven requests inside one minute, out of at most seven logical calls spread over fifteen,
is only possible if retries fire back-to-back. **When two mechanisms could produce a number, find
the case where only one of them can operate.**

The cost was not merely a wrong number. That tier exists as a **cost filter** in front of the *paid*
DeepSeek tier; with its 20 RPD burned by retries it absorbed **0 of 7** fallbacks that session and
sent every one to the billed provider, while the counter read `7` and warned about nothing.

**The tests could not have caught this, and that is the transferable part.** Sixteen tests of the
fallback chain patched `_call_api` wholesale — they replaced the very function that does the
counting, making the relationship between requests and counts structurally unobservable. Widening
their signatures would have kept them green and blind; the two quota tests were therefore rewritten
to drive **real failing clients**. And because unit tests use fake clients, they have no SDK layer at
all and cannot distinguish `max_retries=0` from `max_retries=2` — so the fix was verified by driving
a real `openai` client against a **local 503 endpoint**: 3 requests → 1 per tenacity attempt, same
exception type, so `_should_retry` still sees what it saw. Same lesson as the watchdog's
microseconds: **when a value comes from the outside world, a test that constructs it by hand is
testing your idea of it.**

### 2b. A second program shared the budget, and neither codebase could see it

Google meters **per project AND per model**. `~/.claude/skills/barebone/scripts/vision_ocr.py`
defaulted to `gemini-3.1-flash-lite` — byte-identical to this project's primary tier, on the same
key and project — so the two competed for one 500 RPD and, more sharply, one **15 RPM**. The
dashboard showed flash-lite peaking at **14/15 RPM**: one concurrent request from refusal.

**Both repos were individually correct.** Each picks the free model with the best budget, each
meters its own usage, each has tests. The defect existed only in the *intersection*, which no test,
doc or CI in either project can see. The only artifact that could reveal it is the provider's
dashboard — the shared resource's own view. That is §2a one level up: **a local measurement
disagreeing with the authority that actually enforces the limit.**

**Resolved the same day by the owner, in that repo, and they did both halves**: a key minted in a
**new Google project**, and `DEFAULT_MODEL` moved to **`gemini-3.5-flash-lite`**. Verified from here
by fingerprint — barebone's key is distinct from algo-trade's, which remain byte-identical to each
other (same project, separated by *model*, as intended). **"Different project" is not provable from
a key string**; only the AI Studio project dropdown settles it.

The project split is the half carrying the load. A model rename alone holds only until something
drifts — and `_DEFAULT_MODELS` here silently resolves an unset model to a default, which is exactly
how a rename un-fixes itself.

**⚠️ Unverified, and it is barebone's problem rather than ours: `gemini-3.5-flash-lite`'s RPD is
unknown.** The measured table covers `gemini-3.1-flash-lite` (500 RPD) and "every `gemini-*-flash`"
(20 RPD); a `*-flash-**lite**` at 3.5 is in **neither row**. A 42-image OCR batch dies at image 20
if it meters like a `*-flash`.

### 2c. 23 unpriced observations are correct, and pricing them would be the bug

Every `skipped_active_recommendation` row has `reference_price` NULL, so it can never be marked.
That looks like the `skipped_quota_exhausted` defect recurring. It is the opposite.

The guard fires at `stage_reached='universe'` — before `.info`, before any gate, before any analyst
call — so **no decision was made and no holding period began**. There is nothing for a forward mark
to measure. Verified over all 23: each has a twin observation of the same ticker from the
**previous session**, outcome `recommended`, priced from `.info` — 23/23, lag exactly one session
day — while the funnel's four decision outcomes are **100% priced**.

**Pricing them would create a bias rather than remove one:** a ticker stays blocked for as long as
its recommendation is live, so it would contribute one extra row per blocked day, all echoes of a
single decision, overweighting recommended names by however long their recommendation happened to
sit pending.

The governing distinction is **censoring, not skipping**. `skipped_quota_exhausted` must be priced
because the pipeline *wanted* to evaluate and a budget unrelated to the candidate's merit stopped
it. Ask of any new exit: **did the pipeline decline to decide, or was it stopped from deciding?**
