## ⚠️ Environment — read before running anything

**Always use `.venv`.** It is Python 3.12, matching CI.

```bash
.venv/Scripts/python.exe -m pytest -q      # NOT `pytest`
.venv/Scripts/python.exe main.py           # NOT `python main.py`
```

System Python is **3.14** and the lock pins `pandas==2.2.3`, which has no cp314 wheel — the
locked stack is *physically uninstallable* outside the venv, and `pip install` there silently
resolves forward. **Never `pip install` into system Python for this project.**

**Regenerate the lock IN PLACE, over the existing `requirements.txt`:**

```bash
uv pip compile requirements.in --universal --python-version 3.11 -o requirements.txt
```

Compiling to a *fresh* path anchors nothing and floats every `>=` floor — measured previously,
that drifts 26 packages and takes `openai` 2.41.1 → 3.1.0.

| Mechanism | State | To arm |

`DRY_RUN` and `PAPER_TRADING` are **gone**. `validate()` raises if either appears in the
environment at all, naming the mode the old settings map to. `.env` and `.env.example` are
already migrated.

`paper_trading` gated **nothing** — Schwab's Trader API has no paper endpoint, and the flag was
read only by a startup warning. That is why it was deleted rather than kept: a flag that reads
like a safety layer and is not one is worse than no flag.

**The sink now requires both mode signals to agree.** `execution_mode == "live"` *and*

## The analyst chain — rebuilt on measured data (#32–#34)

**Chain:** `gemini-3.1-flash-lite` (450/day) → `gemini-3.7-flash` (18/day) → `deepseek-v4-flash`.

### The real free-tier limits, from the AI Studio dashboard (2026-08-21)

Metered **per model**, not per provider — this is the fact everything else follows from:

| model | RPM | RPD |
|---|---|---|
| `gemini-3.1-flash-lite` | 15 | **500** |
| every `gemini-*-flash` (2.5, 3, 3.5, 3.6, 3.7) | 5 | **20** |
| `gemma-4-31b-it` | 30 | 14,400 — **banned, parses 0/3** |

**Only the dashboard is trustworthy.** Google removed per-model numbers from the docs, responses
expose no quota headers, and the third-party tables that turn up in search are stale (the best one
found was January 2026, predating every 3.x model, and claimed 250 RPD where the truth is 20).
Acting on one of those produced a wrong conclusion in this session; see the corrections below.

### The primary is chosen for QUOTA, not quality

At **20 RPD**, any `*-flash` primary caps the entire day at ~20 analyst calls — two scheduled scans
of ten tickers each *is* the whole budget. That, not caution, is why `TOP_SP500_COUNT` was 10.
`gemini-3.1-flash-lite` at 500 RPD is the only model on this account that affords a real universe:

    TOP_SP500_COUNT       10 -> 50
    ANALYST_CALL_DELAY_S  12.0 -> 4.0     (60s / 15 RPM)
    ANALYST_DAILY_LIMIT   18 shared -> 450 primary / 18 fallback / 18 fallback2

`gemini-3.7-flash` is the fallback: better per call, but only twenty of them a day.

### `gemma-4-31b-it` is BANNED

It was the configured fallback from April to August 2026 and **parses 0/3, deterministically** —
it echoes the prompt template (`<BUY|HOLD|SKIP>`) and leaks `<thought>` blocks on every call. Every
fallback it ever served was unparseable. Its 14,400 RPD is presumably why it was chosen; quota is
worthless if the output cannot be read. The parse-error fallback added in June 2026 was working
*around* this rather than fixing it.

### Three traps worth not re-learning

1. **This tier reports per-model exhaustion as 503, not 429.** `_should_retry` only short-circuits
   on a `QuotaFailure` detail in the body, so an exhausted model burns all three `@_retry` attempts
   before the fallback engages.
2. **A 503 is as likely to be your own pacing.** The dashboard separates RPM from RPD: probing
   3.7-flash at ~40 RPM against a 5 RPM cap produced 503s that were misread as model instability,
   twice, while the daily budget sat at 6/20.
3. **`analyst_calls` is keyed `(date, provider, model)`.** It was `(date, provider)`, so both
   gemini tiers shared one budget and `all_providers_exhausted` compared a number against itself.
   Legacy rows migrated to `model=''` — those calls really happened, but which model made them is
   unknowable, and charging them to a current model would consume a budget they never touched.

## Conventions that cost something to rediscover

Everything in the 2026-08-16 handoff's equivalent section still holds. New this session:

- **There are TWO broker terminal-status sets.** `TERMINAL_BROKER_STATUSES` (working orders)
  **includes** `REPLACED`; `SWEEP_TERMINAL_BROKER_STATUSES` **excludes** it. Different questions:
  "is this still consuming exposure?" vs "may I free the recommendation?". Merging them is a
  fail-open.
- **`REPLACED` is resolved by following the pointer, never by searching.** The successor carries
  a different price and falls outside any window anchored on the original submission, so a
  matcher finds nothing — and "nothing found" would mark the submission failed while the
  replacement is live.
- **A terminal status is not permission to book a zero fill.** `fills_observed` gates the release
  of capital. A payload with no `filledQuantity`, or a quantity with no execution prices, goes
  through `mark_order_terminal_unobserved` and keeps its FULL commitment at the limit.
- **The index and its release valve must ship together, valve first.** `idx_active_rec_per_ticker`
  covers `approved`; without `complete_recommendation` the first buy of any ticker blocks that
  ticker forever. The migration logs and continues if the database already violates the index,
  rather than refusing to start — an operator who cannot start the bot cannot `/halt` it either.
- **`ticker_recommended_today` does not answer "is there an active recommendation".** It is
  session-scoped. `has_active_recommendation` is the polite check in front of the index.
- **The expiry predicates are complements.** `expires_at <= now` expires; `expires_at > now`
  claims. `<` left a one-second limbo where a row was neither.
- **Three locks, all one-per-running-loop**: `submission_gate()`, `approval_gate()`,
  `scan_lock()`. A module-level `asyncio.Lock` binds to the first loop that *contends* and raises
  for every loop after; `acquire()`'s uncontended fast path hides that from any test that never
  blocks. All three tests contend, on two loops.

## Traps hit during the live run

- **A banner can report a different field from the one that drives behaviour, and read as fact.**
  The scheduler announced "daily scan at 22:00" from the FALLBACK `scan_hour`/`scan_minute` while
  it had actually registered 21:45 and 03:30 from `scan_times` (PR #30). Found only by starting
  the bot and reading its own first line of output. The ETF line beside it was right purely by
  coincidence.
- **A one-off script beats bending the running process.** Triggering a scan without Discord access
  meant stopping the bot and running a throwaway equivalent of `/scan` from the scratchpad — not
  adding a second entry point to the repo, and not running two gateway sessions on one token,
  which would have posted duplicate embeds.
- **"0 recommendations" needs tracing before it is reported.** It was the correct outcome, but only
  checking SNDK against the filter by hand established that: the analyst said BUY and the technical
  filter rejected it on price < MA50. Reporting "0" without that trace would have been indistinguishable
  from reporting a silent failure.
- **`git status` and `git check-ignore` disagreed** about `algo_trade.db.backup-2026-08-21`: status
  does not list it, check-ignore says it is not ignored. `git add -A` will not pick it up today
  (`git ls-files --others` is empty), but do not treat that as protection.

## Traps hit while measuring the analyst models

- **A stale third-party table is worse than no data.** It claimed 250 RPD where the truth is 20,
  and produced the confident and wrong conclusion that the throttle was set to ~7% of its
  allowance. It was at 90% and correctly calibrated. Only the AI Studio dashboard is authoritative.
- **RPM and RPD failures look identical from the client.** Probing at ~40 RPM against a 5 RPM cap
  produced 503s that were read as model instability — twice — while the daily budget sat at 6/20.
  Separate the two before drawing any conclusion.
- **A single successful call proves nothing about parseability.** The historical failure mode here
  is a clean HTTP 200 carrying unparseable text. `gemma-4-31b-it` passes "does it respond" and
  fails "does it parse" 3 times out of 3.
- **A second test passed vacuously this session.**
  `test_the_rebuilt_table_actually_enforces_the_new_key` inserted into the fixture's table rather
  than the migrated one, so a mutation dropping the rebuilt PK survived it. Both vacuous tests this
  session were found the same way: by mutating and watching nothing fail.

## Testing traps hit this session

- **A test can pass vacuously and survive its own mutation.** "The ETF scan shares the stock
  scan's lock" instrumented `get_universe`, which the ETF path never calls. It passed, and the
  mutation giving each scan its own lock **survived it**. Only running the mutation exposed it.
  Instrument something the path under test actually executes.
- **A wrong fixture can be more informative than a right one.** The sweep's fill fixture omitted
  `filledQuantity`; chasing why it failed revealed that `extract_fills`' documented contract
  ("the caller must decide") had no caller honouring it, and that the first implementation booked
  $0 for ten real shares.
- **`git checkout <file>` reverts to HEAD, which does not contain uncommitted work.** Used to undo
  a mutation, it silently deleted a new function. Commit a checkpoint before mutation-testing.
- **An existing test can encode a defect as intent.** `test_expire_stale_does_not_expire_at_exact_now`
  described itself as documenting "the intended boundary semantics" while merely restating what
  the SQL happened to do. It was also latently flaky in the direction of accidentally being right.
- **Adding a guard to a scan loop breaks every test that patches `queries` function-by-function.**
  22 of them. Two harnesses append patches at the end *specifically* to keep positional mock
  indices stable, and say so in a comment; a mid-list insertion breaks them silently.
- **`with A, B:` adds a nested block.** `test_main.py` is at Python's 20-block limit; an autouse
  fixture is the way to add a patch there.
- **Backslash line-continuations and `\n` escapes do not survive being written through some
  shell paths here.** Three edits produced literal newlines inside string literals. Prefer
  `ExitStack` over continuation-joined `with` statements, and build multi-line messages by
  joining a list.
