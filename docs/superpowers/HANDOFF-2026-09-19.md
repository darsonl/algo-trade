## 2. What happened, and the reasoning not in the code

### 2a. The login was moved to Saturday on purpose, and the proof it worked is a timestamp

09-17 §2d recommended a fixed weekly login so the Tuesday warning becomes a backstop rather than a
deadline. This is the first session that acted on it. Saturday is the right slot for a reason
beyond convenience: **no session, so no bot process holds the token file**, and the next scan
(Monday) picks the new token up at startup with nothing to restart.

**What proves a real login happened is `creation_timestamp` moving.** schwab-py writes that field
back verbatim on every token *refresh* and resets it only at login (09-17 §2d). Had this merely
rolled the 30-minute `access_token`, the timestamp would still read 2026-09-16 and the 7-day
window would not have moved at all. It reads 2026-09-19, so the window is genuinely new. Re-derive
it; do not trust the line the script prints, for the same reason 09-18 §2c exists.

`scripts/schwab_login.py` suppresses the authorization URL by default because it contains the app
key — its docstring names "an AI assistant's transcript" explicitly. Do not pass `--show-url` to
make a session easier to follow.

### 2b. A health check that cannot fail is not a health check

CI on #62 was watched with a poll loop built around `jq`. **`jq` is not installed on this host**,
so every stage of the pipeline produced empty output, and the watch reported *nothing* while both
checks went green. It exited 0, having observed nothing, and looked exactly like a quiet CI run.

The bug is not the missing binary, it is that the filter had no way to distinguish **"nothing has
happened yet"** from **"I cannot see anything"** — and defaulted to silence for both. That is the
same shape as `.get("bidPrice", 0)` pricing a sell at give-it-away, and as the `getattr` default
in 09-17 §2b that made a missing attribute indistinguishable from an empty one. This project's
rule — refuse hostile values at every boundary, never default them — applies to throwaway
monitoring too, which is exactly where it keeps getting skipped.

Checking the PR directly took one command and gave the real answer. **Prefer asking the thing
itself over watching a pipe you built.**
