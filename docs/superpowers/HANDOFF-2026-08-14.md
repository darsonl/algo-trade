## ⚠️ START HERE — 3 unfixed Criticals in the Phase 1 spec

From the third Codex review. All verified against the code. **Fix before implementing.**

1. **Kill switch never reaches the sink.** §10 claims "the sink re-reads it" so `/halt` stops an
   in-flight approval, but the predicate written in §2 is
   `execution_mode != "live" or dry_run` — it never checks `trading_enabled`. `/halt` during a
   pending approval does nothing. Self-contradiction inside the spec.
2. **`submit_unknown` reserves no capital and cannot be resolved.** It is absent from
   `COMMITTING_ORDER_STATUSES` in the ledger plan, so a possibly-committed $500 order counts
   as $0 against both ceilings. No operation exists to resolve one — `/reconcile` reads
   positions only, so it cannot tell "working order" from "no order".
3. **`get_positions` has no `raise_for_status`** (`schwab_client/orders.py:142`). A 401/429/500
   JSON body parses to `[]` — "broker has no positions". Guard 8 sees zero exposure, guard 9
   sees no holding. A broker outage *opens* the gate. Contradicts "everything fails closed".

**Plus High:** `approved` can block a ticker permanently — the `completed` transition the spec
specifies exists nowhere (not in the repo, not in `/reconcile`, not in the ledger plan).

**Recommended v3 scope:** fix those three concretely; make `completed` real; bound sells with
limit orders too (currently only buys are bounded); and add a process step requiring every
"X will handle this" claim in a spec to name the file that does it — that class of defect
caused all three Criticals and self-review is blind to it.
