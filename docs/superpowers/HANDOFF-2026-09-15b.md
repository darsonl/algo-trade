### #57 — a provider's error message is not safe to log

Alpha Vantage's free-tier refusal body is literally `We have detected your API key as <KEY> …`.
`news.py` wrapped it in a `RuntimeError` and logged it verbatim: **43 lines** (27 on 09-14, 16 on
09-15). `logs/` is gitignored and the key never reached any ref, so this was plaintext-on-disk, not
a public disclosure — but the repo is public and one pasted log tail closes that gap.

Two more defects in the same function, both found by measuring rather than reading:

- **A spent daily budget was being retried.** The refusal arrives as **HTTP 200**, so nothing in
  transport marks it a failure and the shared `@_retry` slept 2 s + 2 s on every doomed call —
  16 tickers ≈ 64 s. Same shape as the Gemini 503s: *it looked like flakiness and was a spent budget.*
- **No breaker.** The 26th call of a 25-call day cannot succeed and neither can the 27th.

The path had **no tests at all**, which is how it shipped.

### #58 — the news chain, and why Finnhub leads despite worse headlines

`FINNHUB_API_KEY` and `TWELVE_DATA_API_KEY` were added to `.env` but referenced nowhere in code.

**The ordering argument is uniformity, not per-headline quality.** The free tiers are capped on
different axes: Alpha Vantage **25/day**, Finnhub **60/minute** with no daily cap. A per-minute cap
is a pacing problem the scan already solves (`ANALYST_CALL_DELAY_S=4.0` ⇒ ~15/min); a per-day cap
cannot be paced around, and spending it in scan order made headline richness correlate with S&P
rank — measured on 09-15 as a clean step function, positions 0–24 sentiment-scored and 25–40 plain.

**Finnhub's headlines are genuinely worse.** Alpha Vantage ranks by relevance and tags sentiment;
Finnhub's `company-news` is **recency-ordered**, so a thin name gets sector stories tagged to its
ticker ahead of its own news — COR's top three were about AbbVie, Coultreon and Amgen. That cost was
accepted deliberately: the shadow log exists to compare cohorts, and a rank-correlated confound
corrupts exactly that. **Reversing the order is a two-line change if the call is revisited.**

**The docs were wrong twice**, which is why `scripts/probe_news_providers.py` exists: `datetime` is
a Unix epoch int, not the documented ISO 8601, and `category`/`related` are useless as filters. The
probe also calls each provider with a **junk token**, because an error shape is as load-bearing as a
success shape and no success-path test can tell you whether a refusal quotes your key back. Run live
on 09-15: Finnhub answers 401 and does not echo the token; Alpha Vantage's real refusal came back
redacted to `***`, confirming #57 against the actual provider rather than a fixture.

**Twelve Data has no news endpoint at all** — time series, quotes, fundamentals, indicators, insider
transactions, no news. Its key stays deliberately unwired and `.env.example` says so.

### §5.15 investigated — confirmed, and benign

`on_ready` re-firing on a Discord reconnect **has happened**: 2026-04-11 and three times on
2026-08-29. It is not dangerous, and the reason is instructive. Every `add_job` uses a stable `id`
with `replace_existing=True`, so jobs do not duplicate; `scheduler.add_listener` has no such guard
and *does* double-register, but its downstream `schedule_post_scan_shutdown` is id-stable too, so it
collapses back to one job and one duplicated log line. The idempotency discipline applied to jobs
absorbed a bug in the one place it was not applied.

Real residue: `scheduler.start()` raises, discord.py swallows it, and **everything after it in
`on_ready` is skipped** — the close banner, the scheduler summaries, and the restart-inside-the-
window arming. Not fixed; left as a one-line `if not scheduler.running:` when someone wants it.

## 6. Method notes from this session

- **Run the checks against a live session, not the suite.** Every finding this session came from
  the running bot: the credential leak, its 43 occurrences, the rank-correlated confound, and the
  proof that `.info` is live at 09:35. None of it was visible to 1554 passing tests.
- **Measure the provider before writing the parser.** Finnhub's docs were wrong about `datetime`,
  and `category`/`related` looked like relevance filters and are not. The same rule that produced
  `probe_analyst_models.py` produced `probe_news_providers.py`.
- **An error shape is as load-bearing as a success shape.** Alpha Vantage's refusal is HTTP *200*
  and carries a credential; Finnhub's is 401 and does not. Only a junk-token call answers that, so
  the probe makes one per provider.
- **To stop a `@_retry` sleeping in tests, patch `fn.retry.sleep`.** The wait strategy is bound at
  import time, so `patch("module.wait_exponential")` — and even a global `time.sleep` patch — are
  no-ops that look correct while the suite still sleeps. Cost 4 s in one test; caught by `--durations`.
- **`str.replace` fails silently.** Three scripted edits this session no-op'd on whitespace
  mismatches and reported success. Assert the old text is present, or use a tool that errors.
- **A design the docs support can still be wrong for the data.** Alpha Vantage returns strictly
  better headlines and was still demoted, because uniform input across the universe matters more to
  a cohort study than richer input for a rank-selected quarter of it.
- **A reference by informal name evades every automated check.** Two live pointers to the 08-28
  handoff were written as prose (*"the 08-28 handoff"*) and survived a filename grep; one of them
  was an instruction. Before deleting any document, grep the informal form as well — and prefer
  inlining what depends on it over leaving a pointer to chase.
- **Deleting a document is cheap; orphaning what cited it is not.** Everything here is in git, so
  the cost of removal was never the content — it was the references. That reframing is what turned
  "delete the old handoffs" into "index them, and remove the two that nothing needs".
