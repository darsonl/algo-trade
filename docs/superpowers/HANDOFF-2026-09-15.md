## 2. What happened, and the reasoning not in the code

Full entries are in CLAUDE.md *Key Design Decisions*.

### The 2026-09-14 scan (13c §1b checklist)

All green: scan fired 21:45 and finished 22:01; ranking rebuilt with `"dedupe": "cik-v1"` (500 companies,
GOOGL/FOXA/NWSA only); all 50 rows on the forward-P/E gate; **42/50** fundamental passes; 52 analyst calls,
all on `gemini-3.1-flash-lite`; `technical_verdict` column migrated; no Schwab login alert. The ETF scan
recommended BND. **0 stock recommendations** — which led to:

### #53 — the volume gate, removed

- `fetch_technical_data` compared `Volume.iloc[-1]` — **today's still-forming bar during market hours** —
  with a 20-bar average. At 09:45 ET: median ratio 0.087, max 0.339, against 0.5 ⇒ **0 of 42 could pass**.
- **It was already known**: Codex finding #13, with a written fix (`plans/2026-08-14-screener-determinism.md`
  Task 2) that was never executed. Now marked superseded.
- **Removed, not fixed.** Four years of the current S&P 500 on complete bars: it blocked 3.55% of RSI+MA50
  passers, a quarter on half-days/holidays; blocked names did **not** underperform (21d +0.75pp, se ~1.34);
  95% traded $30M+ that day. The completed-bar fix would have moved the holiday artifact one session later.
  Survivorship-biased and price-only: "no evidence it helps".
- `MIN_VOLUME_RATIO` now **fails startup** if set.

### Scan time → 09:35 / 10:00 ET (`.env`, not in git)

User asked for "closer to the open". ETF moved **after** the stock scan because both share `scan_lock` and a
colliding scan is **skipped, not queued**. 09:31 rejected (opening auction); pre-open 09:00 offered, not chosen.

### #54 — exit after the scans, hold the PC awake

- The host sleeps after 45 idle minutes; on 09-14 it slept 08:33→20:06, and the missed run died `0x8007042B`
  with no log line. `WakeToRun` alone is insufficient (timer wakes get a ~2-min unattended idle timeout).
- **Exit is armed by the scheduler's own next-run times**: only scan jobs count as pending (the bell job would
  otherwise read as a scan that never comes); a past run time is not pending (APScheduler emits MISSED first).
- **`scans_done` startup state** stops the 30-min task repeats from restarting the bot after the window.
- **`SetThreadExecutionState(ES_CONTINUOUS|ES_SYSTEM_REQUIRED)`** — Windows withdraws it on exit *or crash*,
  so nothing to restore. Verified on this host (state reads `0x80000001`).
- Decided with the user: **30-min approval window** (buttons answer only while the process lives).
- Verified against a **real** APScheduler run, not only the unit tests.

### #55 / #56 — test hygiene

- `scripts/algo_trade_task.xml` **is tracked** (memory had said otherwise). It declared UTF-16 over UTF-8 bytes,
  so strict parsers refused it; now loads and matches the live task on 12/12 settings.
  **Never regenerate it with `Export-ScheduledTask | Out-File`** — that writes UTF-16 and git sees binary.
- `test_halt_persists_before_waiting_on_the_gate` **flaked on CI 3.11**: a fixed 50 ms wait for work on a
  worker thread. Now waits for the gate's waiter.
- **Test-necessity audit**: almost every test is load-bearing. Removed one exact duplicate, folded three
  identical validation tests into one positive control, patched 18 s of real retry back-off.
  **`trailingPE` in mocks is NOT stale** — production still reads it (prompt, P/E direction, `pe_ratio` column).

## 6. Method notes from this session

- **Run the checks against the first real scan, not only the suite.** The volume bug was invisible to 1523 tests
  because every fixture used complete bars and the only earlier cohort was screened on a Saturday.
- **A known finding with a written plan is not a fix.** Codex #13 sat in a plan for a month while it shipped.
- **Measure whether a rule earns its place before repairing it.** The 4-year study turned "fix the gate" into
  "delete the gate", and showed the planned fix would have kept a holiday artifact.
- **Prove a test is load-bearing by mutating the input its name claims**, and check the mutant is valid —
  a mutation referencing an out-of-scope name failed every test on `NameError` and proved nothing.
- **Identical test bodies are not necessarily duplicates** (same-named module-local helpers; `@patch` decorators).
- **"Doesn't reach X" is not "unused".** The `trailingPE` retraction.
- **A fixed wait for work on another thread is a flake.** Wait for the event.
- **Environment-dependent tests hide in `Config()` defaults.** Changing `.env` on the host broke three.
- **This token cannot run `gh pr edit`/GraphQL (no `read:org`)** — use `gh api` REST for PR creation and edits.
- **Merging is not deployment here**: the task runs from the working tree, so every merge is followed by
  `git pull`, and feature work happens in a separate worktree so the bot's folder stays on `master`.
