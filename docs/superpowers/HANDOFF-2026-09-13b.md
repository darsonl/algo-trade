## 2. What shipped, and the reasoning that is not in the code

Each has a full entry in CLAUDE.md's *Key Design Decisions*. The reasoning worth reading here is
the part a future change is most likely to undo.

### #45 `/market_trend`

Six gauges, each calm / watch / warning / unknown. `screener/market_trend.py`,
`screener/fomc_calendar.py`.

- **Yields come from FRED, not Yahoo.** Yahoo has no 2-year cash yield; `2YY=F` is a futures
  contract and read 4.38 vs the Treasury's 4.56 — enough to fake an inversion.
- **Emergency cuts are judged against the scheduled FOMC calendar**, not by size (Sept 2024 was a
  scheduled 50bp). The effective-date rule needs **both** "on the decision day" and "the weekday
  after": FRED recorded Dec 2015/Dec 2016 same-day and everything since next-day. Oracle test over
  all 31 real `DFEDTARU` changes → exactly 2020-03-04 and 2020-03-16 unscheduled.
- **`fomc_calendar.py` needs extending once a year.** It ends 2027-12-08; after that the gauge
  reports `unknown` and names the file. The dates were scraped from federalreserve.gov — the
  cancelled March 17–18, 2020 meeting is deliberately excluded.
- **Un-inversion within a year is a warning**, not an all-clear.

### #46 Forward P/E gate, dividend floor off

- **Swapping `trailingPE` for `forwardPE` by name would have made the gate LESS safe.** Yahoo omits
  `trailingPE` for a loss-maker (which is what rejected it); `forwardPE` goes *negative*, and a
  negative number is never above the max. `forward_pe_non_positive` carries the protection over.
- **`MAX_PE_RATIO` → `MAX_FORWARD_PE`, and a leftover `MAX_PE_RATIO` fails startup.** The live
  `.env` is already migrated.
- **`recommendations.pe_ratio` still stores trailing P/E.** Changing what an existing column means
  would mislabel older rows. The embed shows Fwd P/E + PEG.
- **PEG < 1 was measured and not gated.** Of 14 PEG<1 names on 08-22, none paid 2%; with the yield
  check skipped for non-payers, PEG<1 + a dividend floor passed only stocks paying nothing.
- **The dividend floor was incoherent, which is why it is off** — not because returns said so. It
  rejected token dividends (META 0.38%) while passing zero dividends (APP). **The 1w returns did
  NOT justify removing it**: yield-rejected −1.16pp vs passed −0.30pp excess is under one standard
  error on one correlated week, and ≥2% payers matched <2% payers. Do not cite them as evidence.

### #47 One ticker per company

- **Identity is the SEC CIK from the Wikipedia constituents table** — verified live: 503 tickers
  collapse to exactly **500** companies. Pairs: GOOGL/GOOG, FOXA/FOX, NWSA/NWS.
- **The most-traded class is kept** (GOOGL 1.5×, FOXA 4×, NWSA 3× — wide and stable).
- **It runs inside the ranking, before the slice**, so the next company takes the freed slot.
- **Fails open**: no CIKs ⇒ rank as before and warn. A duplicate costs one analyst call; a failed
  universe costs the scan.
- **Watchlist tickers are not covered** (no CIK unless in the S&P). `watchlist.txt` is empty.

`_env_str(..., secret=True)` → `field(repr=False)` on nine credential fields. A structural test
fails for any future field named like key/secret/token/hash/password that is not hidden. Guards
accidental disclosure through printed output only.

## 6. Method notes from this session

- **Replay the shadow log before changing a gate.** Every candidate's full `.info` is stored, so
  "what would this rule have passed?" costs seconds and no API calls. It turned "PEG < 1 is safer"
  into "PEG < 1 passes only non-dividend payers" before any code was written.
- **Separate the case for a change from the evidence for it.** The dividend floor came off because
  it was incoherent. The returns pointed the same way but were noise, and the commit says so.
- **An oracle beats a restatement — again.** The emergency-cut rule's first draft was wrong
  (next-day only). Checking against all 31 real FRED changes caught it; a test of my own
  formula would have passed.
- **Adding a field can make old tests vacuous.** Two embed tests asserted `"N/A" in` the whole
  embed; the new PEG field always supplies one. Assert on the specific field.
- **`git checkout <file>` to undo a mutation reverted uncommitted work — for the THIRD time in
  this project**, despite being in memory. Restore from a file copy (`cp`, then `cmp`), or commit
  a checkpoint first.
- **A check you do not gate on is not a check.** A pre-commit scan reported a match and the commit
  and push ran anyway, because they were chained after it rather than conditional on it. It was a
  false positive, by luck. Use `check && git commit`.
- **This repo is public.** Commit messages, PR bodies and handoffs describe secret-handling work
  generically.
- **Float formatting ties.** `15.35` renders `15.3` (it is 15.3499… in binary). Pick test values
  that are not rounding ties.
