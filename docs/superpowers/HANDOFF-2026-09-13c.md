## 2. What shipped, and the reasoning that is not in the code

Full entries are in CLAUDE.md's *Key Design Decisions*.

### #49 DeepSeek fallback2

- **DeepSeek retired V4 Flash on 2026-09-10 and silently broke the paid tier.** `deepseek-v4-flash`
  is *routed* to V4.1 Flash (`deepseek-flash`), which **thinks by default**: reasoning eats the whole
  256-token budget, the reply is `''` with `finish_reason='length'`, and that surfaces as a *parse
  error* naming nothing. Probe: **7/18 thinking on, 18/18 off** (59–94 tokens).
- `openai_request_extras()` sends `thinking: disabled` to the DeepSeek **host** only (not a new
  `_call_api` argument — ~20 tests patch it with 3-arg side effects). The probe shares it and now
  uses the app's 256-token budget; it used 400, measuring a request the app never sends.
- **The chain-order decision (free tier ahead of paid) is unchanged.**
- **Lesson:** a provider can change the model behind an id nobody edited. When a tier's parse
  rate drops with no config change, read the provider changelog and `finish_reason` first.

### #50 `technical_verdict`

- The user asked "do we even need the analyst?". Answer given: **not yet decidable.** Data at the
  time: analyst BUY n=4 **−2.10pp** vs HOLD/SKIP n=7 **+1.09pp** 1w excess — one week, se ≈ 2pp,
  **not evidence**. Verdicts were nearly all HOLD / medium. A decision criterion was *suggested*
  (~100 analyst-judged stocks over 6+ weeks, 1m marks, BUY vs rejects) and **not adopted** — the
  owner's call, deliberately not written into CLAUDE.md.
- **Correction recorded:** CLAUDE.md claimed technicals were skipped for analyst-rejected tickers;
  the code always fetched them. What was missing was the *verdict* (cleared on `rejected_signal`
  so the rejection is not misattributed) and any technicals on quota-exhausted rows.
- Technicals are now fetched **before** the analyst; the gate still decides after it, so **who is
  recommended is unchanged**. Old rows are **not** backfilled (that would apply today's gate logic).

### #51 Schwab login + the order sink

- **`easy_client` discards a token older than 6.5 days and runs an interactive login** (`input()`).
  Approve fetches a quote **even in dry run**, so the first click after a week would have crashed or
  hung holding `approval_gate()`. The token was **155 days dead** on 2026-09-13 and nobody knew.
  `get_client` now loads the file only and raises `SchwabLoginRequired`; `fetch_quote` maps every
  failure to `QuoteUnavailable`; both scans post an expiry alert; `scripts/schwab_login.py` is the
  one place a login happens, and suppresses output because **the authorization URL carries the app key**.
- **Found while tracing callers: the order sink was never given a client.** Both approval views
  called `_call_place_order(None, …)` after the deleted `place_*` wrappers stopped building one, and
  every approval test patched the sink out. A live approval → `AttributeError` → `submit_unknown`:
  nothing sent, capital reserved, ticker blocked behind `/resolve`. Fixed; a login failure at
  submission is `submit_failed`, like `TradingHalted`.
- **First CI run failed** on 3 scan tests: this machine had a fresh token (no alert), CI has none
  (one extra alert). Reproduced locally by pointing the token path at a missing file; fixed with an
  autouse `conftest.py` pin, the same shape as the calendar pin.

### #52 Guard 4 owns staleness

- **Every approval outside the regular session was refused "No usable quote".** Guard 4 accepts the
  last close off-session by design; `fetch_quote` enforced 30 s at any hour, ran first, and handed
  guard 4 `None`. Found when a real Schwab quote on a Sunday came back `StaleQuote`.
- Guard 4's "regular hours" was also a **clock** rule (09:30–16:00 ET) — wrong on weekends, Good
  Friday and after a 13:00 half-day close. Now `market_time.in_regular_session` (real XNYS session
  open/close), and **fail closed** if the calendar cannot answer. `StaleQuote` deleted.

### Also established (no PR)

- **Schwab market data cannot back up yfinance's fundamental gate.** Measured on AAPL/KO/GOOGL:
  Schwab has trailing P/E (matches within ~0.1%), PEG (different method: AAPL 1.93 vs 2.61),
  dividend yield, EPS TTM, ROE, daily candles (matched yf); it has **no forward P/E, no next
  earnings date, no news**. A yfinance outage still rejects every stock (`forward_pe_missing` fails
  closed). **Recommendation: do not build a Schwab fallback for the scan.** yfinance had 0/50 gaps
  in any gating field on the stored cohort.

## 6. Method notes from this session

- **Every bug found this session hid behind a test that replaced the function it lived in.** The
  sink was patched out of every approval test; `fetch_quote` and guard 4 were each tested alone.
  The fix each time was one test driving the *real* pieces together with only the external client
  faked. When a seam is always mocked, ask what the unmocked composition does.
- **A green local suite is one environment.** #51 passed here and failed in CI because this machine
  had a file CI does not. When a feature reads something outside the repo, simulate its absence
  locally (a pytest `-p` plugin patching the path) before pushing.
- **Test the combination, not just the branch.** Before merging #50 after #49, the two were merged
  on a throwaway branch and the full suite run on the result.
- **Mutation-check each fix separately**, and check that a fail-closed branch is actually guarded —
  #52's calendar-failure test passed on the *old* code for an unrelated reason until the branch
  itself was flipped.
- **Parse, don't grep, for structural bans.** The no-login test matched its own explanatory
  docstrings until it walked the AST.
- **Keep the app key out of transcripts.** The Schwab login URL contains it: redirect the flow's
  output to a scratch file, read only status lines, delete the file.
- **`merge` on GitHub is not deployment here.** The scheduled task runs from the working tree, so
  every merge is followed by `git pull`, and the folder is returned to `master` after feature work.
