## 1. Weekday-only task trigger (#68)

**Symptom:** on a weekend evening a cmd window opened every 30 minutes from 20:00 to 00:30 Taipei.
Each was `\AlgoTrade` starting `main.py`, which logged `is not an NYSE trading session — not
starting` and exited (three such lines in `logs/algo_trade.log` on 10-03 by 22:00). Harmless, as
HANDOFF-2026-09-20 already established, but pointless on days that can never be sessions.

**Change:** in `scripts/algo_trade_task.xml`, `ScheduleByDay` (every day) became `ScheduleByWeek`
(Mon–Fri). Start time, the 30-min/4h30m repetition, `IgnoreNew`, `WakeToRun`,
`StartWhenAvailable`, the action and the principal are unchanged.

**Why Mon–Fri in Taipei time is exactly right:** 20:00 Taipei is 08:00 EDT / 07:00 EST on the
**same** weekday, so the Taipei weekday equals the US session weekday. Friday's repeats that run
past local midnight (to ~00:30 Saturday) belong to Friday's trigger, so Friday is fully covered.

**Weekday holidays are deliberately NOT in the trigger.** Good Friday, Thanksgiving and the rest
still start the task and exit on the bot's XNYS check. Encoding them in the trigger would be a
second, manually maintained copy of the exchange calendar.

**Applied live and verified:** `DaysOfWeek=62` (Mon+Tue+Wed+Thu+Fri bits), `WeeksInterval=1`,
principal Darson/Interactive, next run **Mon 2026-10-05 20:00**.

**Registration gotcha (cost two failed attempts):** Task Scheduler rejects the tracked file as-is,
since it is UTF-8 with BOM. `Register-ScheduledTask -Xml` failed with "unable to switch the encoding"
and `schtasks /XML` with "incorrect document syntax". What worked: write a **UTF-16 copy** with
`encoding="UTF-16"` in the declaration to a scratch path, then `schtasks /Create /TN AlgoTrade /XML
<copy> /F`. Keep the tracked file UTF-8; never overwrite it with an export.

**The file and the live task currently disagree on `master`.** The live task is weekdays-only; the
file on `master` still says daily until #68 merges. That has no effect because Task Scheduler never
reads the file, but after merging, `git pull` in the main checkout so they match again.
