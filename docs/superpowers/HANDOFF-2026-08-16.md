## ⚠️ The live database predates the new schema

`algo_trade.db` currently has **no** `orders`, `ops_alerts`, or `kill_switch` tables — the bot has
not been started since they landed. `initialize_db` creates them on the next startup, and the kill
switch will seed from `TRADING_ENABLED` at that moment.

**Consequence:** the first startup after this seeds the switch to **HALTED** (the default), and
with `OPS_USER_IDS` empty nobody is authorized to `/resume` yet.

Run `.venv/Scripts/python.exe scripts/check_ops_ids.py` to see the allowlist and the current
switch state before starting the bot; it exits non-zero when nobody is authorized.

**This is recoverable, and order does not matter** (verified by simulation): set `OPS_USER_IDS`
whenever, restart, and `/resume`. `init()` returns early once state is no longer UNINITIALIZED, so
a restart never reseeds and the halt persists; `Config()` re-reads the environment at
construction, so the new allowlist takes effect on the next process. **Editing the database by
hand is never required.** Setting it before the first run merely saves one restart.

## What is implemented

Phase 0 ledger internals are described in `HANDOFF-2026-08-15.md` and are unchanged. New since:

- **`risk/kill_switch.py`** — durable, cross-process, fail-closed. State is in SQLite so a `/halt`
  in one process stops the others and survives restart; `is_enabled()` re-reads on **every** call
  for exactly that reason. Unknown state — no row, no table, unreadable DB, unrecognised value —
  always reads as not-enabled. `init()` seeds from env only on a database that has never been
  written, so a restart cannot undo an operator's halt. Every transition is audited append-only,
  including the seed.
- **`submission_gate()`** — an `asyncio.Lock`, **one per running event loop**. Enforced at two
  points: the sink (`_call_place_order`, the choke point all `place_*` share) and the approval
  path, held from the final read through broker dispatch. `TradingHalted` is re-raised, never
  rewrapped.
- **`/halt` and `/resume`** — both behind `OPS_USER_IDS`. `/halt` persists **before** awaiting the
  gate, then awaits it so the reply can truthfully say nothing is in flight. It states plainly
  that it cannot recall orders the broker already accepted.
- **`schwab_client/quotes.py`** — validated bid/ask with **no defaults**: every field mandatory,
  every failure raises, transport checked before parsing. Freshness enforced separately
  (`QUOTE_MAX_AGE_S`); `age_seconds` clamps at zero so clock skew cannot fake freshness.
  `marketable_sell_limit` prices `bid * (1 - buffer/100)` rounded **down** to the tick.
- **Sells are DAY marketable limits**; buys stay passive GTC. **No market-order fallback** — no
  usable quote means no sell, and the recommendation re-opens for a human.
- **`ops_alerts` outbox** — `send_ops_alert` persists before delivering; `drain_ops_alerts`
  retries oldest-first at each scan start and stops at the first still-failing alert. Neither send
  nor drain ever raises.

## ✅ Round-5 #7 — after-hours session attribution (BUILT 2026-08-16)

**All round-5 items are now closed.** 820 tests, ruff clean.

`market_time.intended_session_date()` returns *the first session whose close is strictly after
the instant*; `orders.intended_session_date` stores it at insert; `get_day_notional`
equality-matches that column instead of a `submitted_at` range. Friday night and Monday now share
Monday's one ceiling.

Built on `exchange-calendars` (XNYS) — the upstream that `pandas-market-calendars` wraps, so
strictly fewer deps. Anchored, it added exactly 4 packages and drifted nothing.

Two things worth keeping:

- **The lock command in the old version of this doc was a drift trap.** `uv pip compile ... -o
  requirements.txt` only stays anchored because that file already exists and uv treats it as
  preferred pins. Compile to any *other* path and every `>=` floor in `requirements.in` floats:
  doing so today drifts **26 packages** and takes `openai` 2.41.1 → 3.1.0, a major bump that swaps
  its HTTP stack to `httpx2`. Always regenerate **in place**. This is now recorded in
  `requirements.in` itself.
- **The calendar rebuilds when an instant passes its end.** A built calendar spans ~1 year ahead
  and never grows, so a process alive longer would raise `MinuteOutOfBounds` from inside the order
  path. Only the upper bound rebuilds; a too-early instant is bad data and still raises.

The two tests that justify the dependency — Good Friday, and the 13:00 ET close after Thanksgiving
— were each checked against naive implementations first and confirmed to kill them. The
Friday-night test does *not* discriminate a calendar (a weekend-only rule passes it); it is a
regression guard for the original defect, which is a different job.

## Conventions that cost something to rediscover

- **Day bucketing** = US market session via `market_time.market_session_bounds_utc()` as a range
  predicate — for the dupe guard and the analyst quota. **The order ceiling is the exception**: it
  buckets on `orders.intended_session_date` (see #7 above), because "entered Friday" and "trades
  Friday" are not the same claim. Never `'localtime'`, never bare UTC. On this UTC+8 host the 21:45/03:30 scans are one
  session but two local dates.
- **Order CRUD takes `conn`**, unlike the rest of `queries.py`, so cap-check and reservation can
  be one transaction. The ops-alert CRUD follows the same convention for the same future reason.
- **Terminal statuses are an allowlist**, never a denylist — Schwab's enum has a literal `UNKNOWN`.
- **`CREATE TABLE IF NOT EXISTS` does nothing on an existing table.** Every new *column* needs the
  `ALTER TABLE` idiom; `tests/test_db_migrations.py` builds the legacy schema explicitly — add to
  it whenever the schema changes.
- **Tests reaching Schwab must pin `dry_run=True`** regardless of `.env`.
- schwab-py is **1.5.1**. `schwab.Client` does NOT exist; it is `schwab.client.Client`.
  `client.get_quote(symbol, fields=Client.Quote.Fields.QUOTE)` is real and verified.

### Do not "simplify" these back

- **The submission gate must not become a `threading.RLock`.** An RLock is reentrant *per thread*
  and every coroutine shares the loop thread, so `/halt` acquires the "same gate" as an in-flight
  submission and walks straight into the critical section — observed
  `["submit-enter", "halt-acquired", "submit-exit"]`. No mutual exclusion at all, while looking
  correct.
- **The gate must stay one lock per loop.** A module-level `asyncio.Lock` binds to the first loop
  that *contends* on it and raises for every loop after. `acquire()`'s uncontended fast path never
  consults the loop, so this hides from every uncontended test and surfaces in the submission path.
- Both are pinned by `tests/test_kill_switch_gate.py`.
- **Quote parsing must keep having no defaults.** `.get("bidPrice", 0)` on an error body prices a
  sell at give-it-away — the same shape that made `get_positions` read a 401 as "the account holds
  nothing" and *open* the size guards.

### Testing traps hit this session

- **`db_path=":memory:"` means a fresh empty database per connection.** Harmless until something
  reads durable state; then live-mode tests fail for reasons unrelated to what they assert. Use a
  real temp file and seed the kill switch.
- **A test that passes on first write has proven nothing.** Two did this session: a migration
  guard, and a lock test that passed only because the lock was uncontended. Both were made to fail
  first before being trusted.
- **In test code, close SQLite connections in `finally`/`closing()`.** A raising statement left a
  connection open, Windows kept the file locked, and one failure poisoned every later run in the
  session.

### GitHub workflow quirks

- `gh pr edit --base` fails on this PAT (needs `read:org` for GraphQL). Use
  `gh api -X PATCH repos/<owner>/<repo>/pulls/<n> -f base=master`.
- **Retargeting a PR does not trigger CI** — a base change emits `pull_request: edited`, which is
  not a default activity type. Close+reopen via the API emits `reopened`, which is.
- `.github/workflows/ci.yml` only runs for PRs targeting `master`, so a **stacked PR gets no CI**
  until it is retargeted.
